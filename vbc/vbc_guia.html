VBC

Um programa que recebe uma conta como '(3+4)*5' e imprime o resultado. Só existem dígitos de 0 a 9, +, * e parênteses. A given já traz quase tudo; você escreve 3 funções curtas, quase iguais e conserta 6 bugs.

Funções permitidas: malloc calloc realloc free printf isdigit write. Repare que exit não está na lista: por isso o erro tem que "subir" retornando NULL até o main, que faz return (1).

Recebo ou crio o .h?

Na prova você recebe só a given (um .c, normalmente chamado vbc.c ou given.c, igual ao que está comentado em given_comentado.c). Não vem .h nenhum e você não precisa criar um: "Expected files: *.c *.h" só quer dizer que você pode entregar headers se quiser. Entregue um único vbc.c.

O vbc.h do 42_examshell é coisa do simulador

O tester.sh do simulador recusa rodar se não existir rendu/vbc/vbc.h. Para treinar lá, crie um vbc.h vazio com include guard. Pior: a solução de referência do simulador está errada (imprime Unexpected end of file, imprime 0 para entrada vazia, aceita 1++2…). Então as falhas que o tester do simulador mostrar nesses casos são erros do simulador, não seus. Confie no subject.

A ideia: 3 funções, uma por nível de prioridade

Uma conta é uma soma de produtos de fatores. Cada nível vira uma função, e cada função chama a do nível de baixo:

sum = product { '+' product } product = factor { '*' factor } factor = dígito | '(' sum ')'

Quem fica mais fundo na chamada resolve primeiro. sum chama product, então em 3+4*5 o 4*5 já vem pronto antes do + juntar. E o factor chama sum de novo quando vê (: é assim que o parêntese "reinicia" a prioridade.

Árvore gerada para 3+4*5. O eval_tree da given calcula de baixo para cima: 4*5 = 20, depois 3+20 = 23.

Consertos na given

A given vem com bugs de propósito. São 6 mudanças, todas pequenas:

  1. Include. #include <malloc.h> vira #include <stdlib.h> (o próprio comentário avisa).
  2. Linha lixo. Apague node *n(**s);: não compila.
  3. accept não compara. Ele consome qualquer caractere. Troque a condição: 
    if (**s)        →        if (**s == c)
  4. O buraco //...: escreva parse_factor, parse_product, parse_sum (próxima seção).
  5. parse_expr: comece com ret = parse_sum(&s), devolva NULL se falhar, e quando sobrar caractere imprima unexpected(*s) antes do destroy_tree. A given não imprime nada aí.
  6. eval_tree: coloque return (0); depois do switch. Sem isso, -Wall -Werror dá "control reaches end of non-void function".

As funções, uma a uma

1. parse_factor: o átomo

Três caminhos: é dígito → cria folha; é ( → chama parse_sum e exige ); senão → erro com o caractere atual (se for '\0', o unexpected já imprime "end of input").

node    *parse_sum(char **s);   // protótipo: factor chama sum

node    *parse_factor(char **s)
{
    node    *ret;

    if (isdigit(**s))
    {
        ret = new_node((node){.type = VAL, .val = **s - '0'});
        (*s)++;
        return (ret);
    }
    if (accept(s, '('))
    {
        ret = parse_sum(s);
        if (!ret)
            return (NULL);
        if (!expect(s, ')'))
        {
            destroy_tree(ret);
            return (NULL);
        }
        return (ret);
    }
    unexpected(**s);
    return (NULL);
}
(node){.type = VAL, .val = 5}

É um compound literal: cria um node temporário na hora, com os campos não citados zerados. O new_node da given copia ele para o heap. Poupa declarar variável tmp.

2. parse_product: fatores ligados por *

Lê um fator à esquerda. Enquanto vier *: lê outro fator e junta os dois num nó MULTI, que vira o novo "esquerda".

node    *parse_product(char **s)
{
    node    *left;
    node    *right;

    left = parse_factor(s);
    if (!left)
        return (NULL);
    while (accept(s, '*'))
    {
        right = parse_factor(s);
        if (!right)
        {
            destroy_tree(left);
            return (NULL);
        }
        left = new_node((node){.type = MULTI, .l = left, .r = right});
    }
    return (left);
}

3. parse_sum: cópia do product

Exatamente o mesmo código, trocando 3 coisas: parse_factor → parse_product, '*' → '+', MULTI → ADD.

node    *parse_sum(char **s)
{
    node    *left;
    node    *right;

    left = parse_product(s);
    if (!left)
        return (NULL);
    while (accept(s, '+'))
    {
        right = parse_product(s);
        if (!right)
        {
            destroy_tree(left);
            return (NULL);
        }
        left = new_node((node){.type = ADD, .l = left, .r = right});
    }
    return (left);
}

4. parse_expr: a porta de entrada

Se parse_sum terminou mas ainda tem caractere sobrando, é lixo no final (um ) a mais, dois dígitos seguidos…).

node    *parse_expr(char *s)
{
    node    *ret;

    ret = parse_sum(&s);
    if (!ret)
        return (NULL);
    if (*s)
    {
        unexpected(*s);
        destroy_tree(ret);
        return (NULL);
    }
    return (ret);
}
Por que char **s?

Todas as funções andam pela mesma string. Passando o endereço do ponteiro, quando parse_factor faz (*s)++, quem chamou também "vê" que o cursor andou. É por isso que parse_expr passa &s.

Como os erros saem (sem código extra)

  
Você não precisa contar parênteses nem validar a string antes. Todo erro aparece sozinho em um de três lugares:

  

    
OndeQuandoExemplos

    
parse_factoresperava dígito ou ( e veio outra coisa1+ → end of input · 1++2 → '+' · abc → 'a' · () → ')'

    
expect(s, ')')fechou a soma dentro do parêntese mas não veio )((1+2)*3 → end of input · (1+12) → '2'

    
parse_exprsobrou caractere no fim1+2) → ')' · 12 → '2' · 1 + 2 → ' '

  

  
Depois de imprimir, cada função libera o que já construiu (destroy_tree(left)) e devolve NULL, até chegar no main, que retorna 1. Sem leaks.

Roteiro para decorar

  
Na prova, faça nesta ordem:

  
    
    
  • Trocar malloc.h → stdlib.h e apagar node *n(**s);
    • 
    
  • accept: if (**s == c)
    • 
    
  • eval_tree: return (0); no final
    • 
    
  • Escrever parse_product (o "molde": left, while accept, right, if !right destroy, left = new_node)
    • 
    
  • Copiar e colar como parse_sum, trocando factor→product, *→+, MULTI→ADD
    • 
    
  • Escrever parse_factor (dígito / ( sum expect ) / unexpected) + protótipo de parse_sum antes dele
    • 
    
  • parse_expr: parse_sum(&s), checar NULL, e unexpected(*s) se sobrou
    • 
    
  • Testar: '3+4*5'=23, '(3+4)*5'=35, '1+', '1+2)', ''
    • 
  

  
Frase para lembrar a ordem das chamadas: "soma de produtos de fatores; fator é dígito ou parêntese com soma dentro".
