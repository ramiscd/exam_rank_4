Exam Rank 04 · argo

Guia do Argo

O argo é um parser de JSON bem pequeno. Ele lê um arquivo caractere por caractere, monta uma árvore em memória e o main que já vem pronto imprime essa árvore de volta. Se a saída for igual à entrada, o seu parser funciona.

Você terminou o projeto quando…

…conseguir escrever estas cinco funções de memória e elas passarem nos testes. Todo o resto do arquivo vem pronto no given.c.

  • argo(dst, stream): chama o parser e devolve 1 ou -1.
  • parser(dst, stream): olha o próximo caractere e decide se vem um número, uma string ou um mapa.
  • parse_int(dst, stream): lê um inteiro com fscanf("%d").
  • get_str(stream): lê uma string entre aspas e trata \" e \\.
  • parse_map(dst, stream): lê { "chave":valor, … } e chama parser de novo para cada valor. Essa é a recursão.

O que você recebe e o que você entrega

O given.c já tem as structs, quatro funções auxiliares de leitura, o free_json, o serialize e o main. O argo.c que você entrega é o given.c inteiro com as suas funções coladas antes do main.

Use o unexpected() do given, não reescreva a mensagem

O subject escreve "Unexpected token" com U maiúsculo, mas os exemplos e o código dado usam minúsculo. A saída é comparada com a do código de referência, então chamar unexpected(stream) sempre garante o texto certo.

Funções permitidas: getc, ungetc, printf, malloc, calloc, realloc, free, isdigit, fscanf, write.

A struct json: um tipo, três formas

Todo valor JSON vira um json. O campo type diz qual dos três ele é, e a union guarda o dado correspondente. Numa union os campos dividem a mesma memória, então só o campo que combina com type tem conteúdo válido.

typedef struct json {
	enum { MAP, INTEGER, STRING } type;   // qual "forma" este valor tem
	union {
		struct {
			struct pair *data;   // array de pares chave/valor
			size_t       size;   // quantos pares
		} map;                   // usado quando type == MAP
		int   integer;           // usado quando type == INTEGER
		char *string;            // usado quando type == STRING
	};
} json;

typedef struct pair {
	char *key;    // a chave é sempre uma string
	json  value;  // o valor é outro json (aqui entra a recursão)
} pair;

Exemplo: a árvore de {"tomatoes":42,"potatoes":234}

json  type=MAP  size=2
├── data[0]  key="tomatoes"  value: json type=INTEGER integer=42
└── data[1]  key="potatoes"  value: json type=INTEGER integer=234

E de {"recursion":{"recursion":"recursion"}}

json  type=MAP  size=1
└── data[0]  key="recursion"
             value: json type=MAP size=1          ← um mapa dentro de um pair
                    └── data[0] key="recursion"
                                value: json type=STRING string="recursion"

Como pair.value é um json, um mapa pode conter outro mapa sem limite de profundidade. Por isso o parse_map chama o parser para ler cada valor.

Lendo o stream: um cursor que só anda para frente

Pense no arquivo como uma fita. getc lê o caractere do cursor e avança. ungetc devolve um caractere. As funções do given montam três operações em cima disso:

int peek(FILE *stream)            // olha sem consumir
{
	int c = getc(stream);
	ungetc(c, stream);
	return c;
}

void unexpected(FILE *stream)     // imprime o erro com base no próximo caractere
{
	if (peek(stream) != EOF)
		printf("unexpected token '%c'\n", peek(stream));
	else
		printf("unexpected end of input\n");
}

int accept(FILE *stream, char c)  // consome se for c (sem erro)
{
	if (peek(stream) == c)
	{
		(void)getc(stream);
		return 1;
	}
	return 0;
}

int expect(FILE *stream, char c)  // consome se for c, senão imprime erro
{
	if (accept(stream, c))
		return 1;
	unexpected(stream);
	return 0;
}
Detalhe importante do unexpected

Ele imprime o caractere que ainda não foi lido. Por isso, ao achar um erro, chame unexpected antes de consumir o caractere problemático. Se você já consumiu com getc, a mensagem vai mostrar o caractere seguinte.

A gramática: o que é um valor válido

O subject pede só três tipos e proíbe espaços. A gramática inteira cabe em quatro linhas:

valor  :=  inteiro  |  string  |  mapa
inteiro:=  o que scanf("%d") aceita      ex: 42   -7
string :=  '"'  { caractere | '\"' | '\\' }  '"'
mapa   :=  '{'  '}'
        |  '{'  string ':' valor  { ',' string ':' valor }  '}'

O primeiro caractere decide o tipo. Essa é a função do parser:

As 5 funções, uma por vez

Escreva nesta ordem, da mais simples para a mais complexa. A cada uma, você consegue testar mais casos.

1. argo: a porta de entrada

Só repassa para o parser e converte o resultado para o formato do subject (1 sucesso, -1 falha).

int	argo(json *dst, FILE *stream)
{
	if (parser(dst, stream) == -1)
		return (-1);
	return (1);
}

2. parser: decide o tipo pelo primeiro caractere

int	parser(json *dst, FILE *stream)
{
	int	c = peek(stream);          // int, não char: precisa caber EOF

	dst->type = INTEGER;           // valor "seguro": se der erro, free_json não lê lixo
	if (isdigit(c) || c == '-')    // número (scanf("%d") aceita negativo)
		return (parse_int(dst, stream));
	if (c == '"')                  // string
	{
		dst->type = STRING;
		dst->string = get_str(stream);
		if (dst->string == NULL)
			return (-1);
		return (1);
	}
	if (c == '{')                  // mapa
		return (parse_map(dst, stream));
	unexpected(stream);            // qualquer outra coisa, inclusive EOF e espaço
	return (-1);
}
Por que dst->type = INTEGER logo no começo?

Quando argo falha, o main chama free_json(file). Se o erro acontecer antes de você preencher type, o free_json vai ler memória não inicializada e pode tentar dar free num ponteiro aleatório. Com INTEGER, o free_json não faz nada. Uma linha resolve.

3. parse_int: deixe o fscanf trabalhar

int	parse_int(json *dst, FILE *stream)
{
	int	n;

	if (fscanf(stream, "%d", &n) != 1)   // ex: "-" sozinho ou "-x"
	{
		unexpected(stream);
		return (-1);
	}
	dst->type = INTEGER;
	dst->integer = n;
	return (1);
}

fscanf lê todos os dígitos seguidos e para no primeiro caractere que não é dígito, sem consumi-lo. Em 42, ele lê 42 e deixa a , para o parse_map.

4. get_str: string com escape

Consome a aspa de abertura e copia caracteres até a aspa de fechamento. Se aparecer \, pula a barra e copia o próximo caractere literalmente, seja ele " ou \. Se o arquivo acabar antes da aspa de fechamento, é erro.

char	*get_str(FILE *stream)
{
	char	*res = calloc(4096, sizeof(char));   // calloc já deixa o '\0' no final
	int		i = 0;
	int		c;                                   // int para comparar com EOF

	getc(stream);                   // consome a aspa de abertura
	while (1)
	{
		c = getc(stream);
		if (c == '"')               // aspa sem barra antes: fim da string
			break ;
		if (c == '\\')              // barra: o próximo caractere é literal
			c = getc(stream);
		if (c == EOF)               // acabou o arquivo no meio da string
		{
			free(res);
			unexpected(stream);     // imprime "unexpected end of input"
			return (NULL);
		}
		res[i++] = c;
	}
	return (res);
}

Entrada "escape! \" "

  • " abertura, consumida
  • escape! copiado
  • \ vê a barra e lê o próximo: " é copiado
  • copiado
  • " fim

Na memória fica escape! " . O serialize recoloca a barra na hora de imprimir.

Entrada "unfinished string 2\"

  • copia unfinished string 2
  • \ lê o próximo: " é copiado, não fecha
  • getc devolve EOF
  • imprime unexpected end of input

A aspa escapada não termina a string. É exatamente isso que esse teste verifica.

5. parse_map: o laço com recursão

O mapa é um laço de "chave : valor", separado por , e terminado por }. Para o valor, chame o parser: é ele que permite um mapa dentro de outro.

int	parse_map(json *dst, FILE *stream)
{
	pair	*cur;

	dst->type = MAP;
	dst->map.size = 0;
	dst->map.data = NULL;
	getc(stream);                       // consome '{'
	if (accept(stream, '}'))            // mapa vazio: {}
		return (1);
	while (1)
	{
		if (peek(stream) != '"')        // chave tem que ser string
		{
			unexpected(stream);
			return (-1);
		}
		// aumenta o array em 1 pair
		dst->map.data = realloc(dst->map.data, (dst->map.size + 1) * sizeof(pair));
		cur = &dst->map.data[dst->map.size];
		cur->key = get_str(stream);
		if (cur->key == NULL)
			return (-1);
		dst->map.size++;                // só conta o par depois que a chave existe
		if (!expect(stream, ':'))
			return (-1);
		if (parser(&cur->value, stream) == -1)   // RECURSÃO
			return (-1);
		if (accept(stream, '}'))        // fim do mapa
			return (1);
		if (!expect(stream, ','))       // senão tem que ter vírgula
			return (-1);
	}
}
Por que size++ fica entre a chave e o valor

O free_json libera data[0] até data[size-1]. Se a chave falhar, o par não é contado e nada inválido é liberado. Se o valor falhar, o par é contado, e o parser já colocou um type válido no valor, então o free_json libera tudo sem leak e sem crash.

    Ponto em aberto: lixo depois do valor
    
Nem a referência nem este guia reclamam de algo como 1x ou {}}: o parser lê o primeiro valor e ignora o resto. O tester fornecido não testa isso. Se quiser ser mais rigoroso, dá para adicionar no argo, depois do parser: if (peek(stream) != EOF) { unexpected(stream); return (-1); }. A desvantagem é que um arquivo terminado em \n passaria a dar erro. Os exemplos do subject usam echo -n, então isso não quebraria nenhum deles, mas eu não tenho como confirmar qual comportamento a correção da prova espera.

  

  

    Limite que continua existindo
    
Strings maiores que 4095 caracteres estouram o buffer do calloc(4096). A referência tem o mesmo limite e os testes usam strings curtas, então mantive o código simples. Se quiser eliminar o limite, troque por um buffer que cresce com realloc.

  






  
Arquivo final e como testar

  
Monte o argo.c assim: copie o given.c inteiro e cole as funções abaixo logo antes do main. A primeira linha é um protótipo, porque parse_map chama parser antes de ele estar definido.


int	parser(json *dst, FILE *stream);

int	parse_int(json *dst, FILE *stream)
{
	int	n;

	if (fscanf(stream, "%d", &n) != 1)
	{
		unexpected(stream);
		return (-1);
	}
	dst->type = INTEGER;
	dst->integer = n;
	return (1);
}

char	*get_str(FILE *stream)
{
	char	*res = calloc(4096, sizeof(char));
	int		i = 0;
	int		c;

	getc(stream);
	while (1)
	{
		c = getc(stream);
		if (c == '"')
			break ;
		if (c == '\\')
			c = getc(stream);
		if (c == EOF)
		{
			free(res);
			unexpected(stream);
			return (NULL);
		}
		res[i++] = c;
	}
	return (res);
}

int	parse_map(json *dst, FILE *stream)
{
	pair	*cur;

	dst->type = MAP;
	dst->map.size = 0;
	dst->map.data = NULL;
	getc(stream);
	if (accept(stream, '}'))
		return (1);
	while (1)
	{
		if (peek(stream) != '"')
		{
			unexpected(stream);
			return (-1);
		}
		dst->map.data = realloc(dst->map.data, (dst->map.size + 1) * sizeof(pair));
		cur = &dst->map.data[dst->map.size];
		cur->key = get_str(stream);
		if (cur->key == NULL)
			return (-1);
		dst->map.size++;
		if (!expect(stream, ':'))
			return (-1);
		if (parser(&cur->value, stream) == -1)
			return (-1);
		if (accept(stream, '}'))
			return (1);
		if (!expect(stream, ','))
			return (-1);
	}
}

int	parser(json *dst, FILE *stream)
{
	int	c = peek(stream);

	dst->type = INTEGER;
	if (isdigit(c) || c == '-')
		return (parse_int(dst, stream));
	if (c == '"')
	{
		dst->type = STRING;
		dst->string = get_str(stream);
		if (dst->string == NULL)
			return (-1);
		return (1);
	}
	if (c == '{')
		return (parse_map(dst, stream));
	unexpected(stream);
	return (-1);
}

int	argo(json *dst, FILE *stream)
{
	if (parser(dst, stream) == -1)
		return (-1);
	return (1);
}

O tester.sh da pasta de referência compara a sua versão com a referência, mas procura o seu arquivo em ../../../../rendu/argo/argo.c. Para usar aqui, troque a variável USR pelo caminho do seu argo.c. Lembre que ele compara com a referência, então os casos -42 e {"a":{},"b":1} não aparecem lá.
